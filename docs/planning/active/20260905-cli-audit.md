# Make the command line safe to drive from a script or an agent

This ExecPlan is a living document. The sections `Progress`, `Surprises &
Discoveries`, `Decision Log`, and `Outcomes & Retrospective` must be kept up
to date as work proceeds.

## Purpose / Big Picture

`teanode` is the client: it administers a server over the API, and the
comments in `internal/cmd` say who it is for — a person at a terminal, a
deployment script, and a language model driving the tool. On 2026-09-05 the
built client was run command by command against the live server at
https://mail.teanode.com, from a laptop with a saved profile and from the
console inside the deployed container, and compared with `mc`, a sibling
command-line client whose README records what it learned the hard way from
agents and scripts driving it. Everything that reads worked. What follows is
what did not hold up for a script, and what a person would trip on.

After this change a script or an agent driving `teanode` gets a refusal it can
parse instead of a prompt it cannot answer, an exit code that says what kind
of thing went wrong, an error it can decode when it asked for JSON, and a way
to sign in to a server that cannot change it. A person gets a confirmation
before every deletion rather than before some of them, a note when a list was
cut short, and messages that say what was wrong rather than what the server's
error value is called.

## Surprises & Discoveries

- Observation: the client inside the deployed container is a version behind
  the server it sits next to. `teanode version` there says v0.4.2-1-g17c3cf0
  while `teanode server status` says 0.4.3. An in-place upgrade stages only
  `teanode-server` (see `internal/upgrade/exec.go`), by design since #22, so
  the console's client is whatever the image shipped. It works, because the
  client goes through the API and reads the schema, but it is worth knowing
  when a console command lacks a flag the docs mention.
- Observation: a bad token over the network came back as `api: not logged in`
  with HTTP 200, so the client's 401 branch never ran and the message was
  the server's error value rather than "sign in again".
  Evidence: `teanode --url https://mail.teanode.com --token tnt_bogus domain
  list` printed `api: not logged in`, exit 1.
- Observation: `teanode mail list --status bogus` printed `no mail matches`
  and exited 0, so a typo in a filter looks like an empty server.
- Observation: a confirmation with standard input closed printed the whole
  prompt and then `cancelled`; a script that forgot `--force` got a prompt it
  could not see and an error that does not say what to do.
- Observation: `teanode token revoke <unknown>` said `web: session is not
  valid`, because `authenticator.RevokeToken` reuses the session error for a
  token that is not the caller's.
- Observation: `teanode passkey list` showed the last-used address as
  `15.158.27.49:5196`. Sessions record the address without the port; the
  passkey path in `internal/api/v1api/apigraph/passkey.go` recorded
  `request.RemoteAddr` as it was.
- Observation: `teanode server identity` reports the greeting name
  `mail.teanode.com` no longer resolves to the relay's address, since the
  name moved to CloudFront on 2026-09-05. The reverse name still
  forward-confirms, which is what the large receivers check. Not a client
  problem; recorded for the operator.
- Observation: unknown commands exited 3, everything else 1. The 3 is
  urfave's default for "No help topic", and it collides with the code this
  plan gives a read-only refusal.

## Decision Log

- Decision: adopt `mc`'s read-only profile, but opt in rather than the
  default. Rationale: `teanode`'s existing users and scripts sign in and
  expect to write; a client that refused until told otherwise would break
  every one of them on upgrade. An agent, or a person handing an agent a
  profile, opts in with `--read-only` at login or the environment variable,
  which cannot be overridden the other way. Date/Author: 2026-09-05, session.
- Decision: detect a mutation by tokenising the GraphQL document rather than
  by which client function was called. Rationale: `teanode api graphql` takes
  a document written by hand, and a check on the function name would not
  see it. The tokeniser strips comments and strings, so a field called
  `mutation` inside a query does not trip it and a keyword hidden in a string
  cannot hide. Date/Author: 2026-09-05, session.
- Decision: `auth logout` revokes the token even on a read-only profile.
  Rationale: forgetting a profile without revoking its token leaves a live
  credential nobody can see from this machine, which is worse than the
  one mutation logout makes, and logout is the reader's explicit act.
  Date/Author: 2026-09-05, session.
- Decision: exit codes follow `mc`'s numbering (3 read-only, 4 not found, 5
  token refused, 6 unreachable) with 2 for usage. Rationale: the people who
  drive both tools already know these. Date/Author: 2026-09-05, session.
- Decision: leave `token revoke` and `session revoke` without a confirmation.
  Rationale: they name one credential, and a revoked one is replaced by
  issuing another; the deletions that confirm are the ones that lose
  something — a password, an account, an authenticator. Date/Author:
  2026-09-05, session.

## Outcomes & Retrospective

Every item in the plan landed, and the two server-side fixes could only be
proved by unit test: the live server still runs the release before this
change, so `token revoke <unknown>` there still says `web: session is not
valid` and `passkey list` still shows a port, until it is upgraded.

What the audit did not change, and why: the container's client being a
version behind its server is a consequence of #22 and is the right trade;
the greeting name not resolving to the relay is a deployment question for
the operator, not the client; `token revoke` and `session revoke` do not
confirm, by decision. `mc`'s `--fields` projection, CSV output and
multi-profile fan-out were considered and left out: `--json` piped to `jq`
covers the first two, and there is one server.

The lesson worth keeping is the one `mc` had already written down: a tool
that will be driven by something that cannot read a prompt has to refuse
rather than ask, and has to fail in the format it succeeds in. Both were
cheap to add and would have been expensive to discover from a stuck
pipeline.

## Context and Orientation

`cmd/teanode/main.go` builds the root command with urfave/cli v3 and runs it;
every subcommand is in `internal/cmd`, one file per group. `internal/client`
is the GraphQL client they share: `Execute` in `client.go` posts a document
and decodes the reply, and the rest of the package is one function per
operation. Commands reach a server through `openClient` in
`internal/cmd/client.go`, which resolves where to go — `--url`, `--profile`,
the active profile, or the console — and `describeConnectionError` there
rewrites a refused connection into advice. Output helpers are in
`internal/cmd/output.go`: `PrintJSON`, `JSONFlag`, `ForceFlag`, `confirm`.
Profiles are `internal/cmd/profile.go`, one JSON file under the user's
configuration directory.

A "mutation" is a GraphQL operation that changes something; the client writes
its own as `mutation (...) { ... }`. A "read-only profile" is a saved server
whose client refuses to send a mutation, checked on this machine before the
request is made.

## Plan of Work

In `internal/client`, add `errors.go` with `ErrUnauthorized`, `ErrNotFound`,
`ConnectionError` and `ReadOnlyError`, and make `Execute` and `Download`
return them: the connection error wraps the transport failure; the
unauthorized error is returned for HTTP 401 and for a GraphQL error whose
message is the server's `api: not logged in`; the not-found error for `api:
not found`. Add `mutation.go` with `IsMutationDocument`, a tokeniser that
skips comments and strings and reports whether any operation keyword at the
top level is `mutation`. Give `Options` a `ReadOnly` field that `Execute`
honours before doing anything else.

In `internal/cmd`, rename `describeConnectionError` to `describeError` and
make it handle the three typed errors; add `describeNotFound(err, what)` for
the commands that name one thing. In `output.go`, `confirm` checks whether
standard input is a terminal and refuses with a `--force` hint when it is
not; `ForceFlag` reads `TEANODE_FORCE`; `JSONFlag` records that JSON was
asked for so `main` can print the error as JSON. Add `exit.go` with
`ExitCode(err)`. In `profile.go`, add `ReadOnly`; in `auth.go`, the
`--read-only` login flag, the `set-read-only` command, the column in `list`
and the line in `status`; in `client.go`, the global flag and the variable
feed the client's option. Add confirmations to `alias delete`, `credential
delete`, `user delete` and `passkey delete`. Validate the enumerated filters
in `mail.go`. Print a note to standard error when a list came back exactly as
long as `--first`. Let `auth login` with no `--url` re-sign in to the active
profile. Let `token create` print the server's real address.

In `cmd/teanode/main.go`, add the `--read-only` global flag, a
`CommandNotFound` that prints a usable message and exits 2, and an error
handler that prints JSON when JSON was asked for and exits with the mapped
code.

On the server, strip the port in `apigraph/passkey.go` where the passkey's
last use is recorded, and return `api.ErrNotFound` from
`authenticator.RevokeToken` for a token that is not there.

Update `docs/reference/command-line.md`: a section on running from a script
(non-interactive confirmations, `TEANODE_FORCE`, JSON errors, exit codes),
read-only profiles, and the completion command. Tests: `IsMutationDocument`,
the exit-code mapping, the error rewriting, the capped-list note, the
profile field round trip.

Validation: `make build`, `make test`, `make lint`; then from the worktree,
`./build/teanode --read-only alias create zhou.io --kind null --pattern x`
must refuse with exit 3 and nothing sent; `echo | ./build/teanode domain
delete zhou.io` must refuse with a `--force` hint and exit 2 without
printing the prompt; `./build/teanode mail get nope --json` must print
`{"error": ...}` on standard error and exit 4.
